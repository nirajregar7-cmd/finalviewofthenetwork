# Working in this repo (Base44 sandbox)

pnpm workspace: `artifacts/the-network` (Vite + React SPA), `artifacts/api-server`
(Express 5 API), `lib/*` (db schema, api-spec, zod, generated client).
`lib/db` schema is only imported as `@workspace/db/schema`; the API never uses
`lib/db/src/index.ts` at runtime.

## Running it

```bash
docker compose -f docker-compose.base44.yml up -d --build
```

- `web` (artifacts/the-network) is the public entry point on host port 3000; it is
  the only published port. Vite proxies `/api` and `/socket.io` to
  `API_PROXY_TARGET=http://api:3001`, so the app is single-origin (session cookies
  work without CORS).
- `api` listens on 3001 inside the compose network only.
- `deps` is a one-shot service that runs `pnpm install --frozen-lockfile` into the
  bind-mounted repo. **After changing any package.json or the lockfile**, re-run it
  before restarting the app services:
  ```bash
  docker compose -f docker-compose.base44.yml up -d --force-recreate deps
  docker compose -f docker-compose.base44.yml up -d
  ```

## Non-obvious quirks

- **PostgreSQL needs TLS.** `artifacts/api-server/src/db.ts` always connects with
  `ssl: { rejectUnauthorized: true }` and refuses to start without
  `NEON_DATABASE_URL`. The local `db` service therefore runs with `ssl=on` using a
  throwaway CA/cert generated by the one-shot `db-certs` service into the `dbcerts`
  volume, and `api` trusts it via `NODE_EXTRA_CA_CERTS=/certs/ca.crt`. Without that
  CA the API exits with "Neon PostgreSQL is unavailable".
- **The schema is self-migrating.** The API runs its own `CREATE TABLE IF NOT
  EXISTS ...` block plus seed SQL before `listen()` (see the end of
  `artifacts/api-server/src/legacy-app.ts`), so no separate migration step is
  needed; seeds for communities/aptitude run on first boot.
- **The API "dev" script does not watch files** — it is
  `pnpm build && pnpm start` (esbuild bundle). Frontend edits hot-reload; backend
  edits need `docker compose -f docker-compose.base44.yml restart api`.
- Vite dev requires `PORT` and `BASE_PATH` (compose sets 3000 and `/`); its config
  already allows any host, so the sandbox preview host needs no allowlist change.
- Optional integrations are guarded and log warnings when unset: email
  (`BREVO_API_KEY` or `SMTP_*`, needed for the sign-up / password-reset OTP),
  push (`VAPID_*`), FCM (`FCM_SERVICE_ACCOUNT_JSON`). The API boots fine without
  them, but **new account registration cannot complete without email delivery**
  (registration is OTP-gated; there are no seeded accounts — sign in with an
  existing account or create one through the flow).
- `REPLIT_API_ORIGIN` / Firebase / Cloudflare hosts in `src/api.ts` only change the
  API origin on those hostnames; on the sandbox preview host requests stay relative.

## Checking things

```bash
curl -s localhost:3000/ | head            # Vite dev HTML
curl -s localhost:3000/api/healthz        # {"status":"ok"}
docker compose -f docker-compose.base44.yml exec -T api pnpm run typecheck
docker compose -f docker-compose.base44.yml exec -T web pnpm run typecheck
docker compose -f docker-compose.base44.yml exec -T api node --test src/post-engagement.test.mjs
```
